# AI 幻觉防卫 SOP

模型凭训练记忆「编造」看似合理的 API 与包名——代码看起来对、评审肉眼难辨，
运行即炸（幻觉 API），或被攻击者抢注包名投毒（幻觉依赖，slopsquatting）。
这是 AI 生成代码**特有**的缺陷类，人类几乎不写这种 bug。本 SOP 供 author（提交前自查）、
sentinel（入口扫描）与评审（复核）使用；核心原则：**以实际安装版本与 registry 事实为准，
永远不以模型记忆为准**。

## 识别信号

- `ImportError`、`AttributeError`、`ModuleNotFoundError`；类型检查报未知符号。
- 「记得有但查不到」的方法：调用名与库文档不符、参数名对不上、返回值类型不符。
- 使用了依赖清单中不存在的包，或代码 import 与声明依赖不一致。
- 新增依赖：包名陌生、与知名包名高度相似（`requets`/`beautifulsoup4` 类形近）、
  下载量极低、刚注册、无源码仓库链接。

## 定位步骤

1. 列出 diff 中全部外部符号（import 的模块、调用的函数/类/方法）。
2. 对照**实际安装版本**核验：用 `inspect.signature`、源码或官方文档逐个核对
   符号存在性、参数名、默认值、返回值类型——四项全对才算通过。
3. 版本核对：代码用法与锁定版本是否匹配；模型记忆常混用新旧版本 API。
4. 新增/变更依赖：到 registry（PyPI 等）核验包存在性、首次发布时间、维护者、
   下载量级、与知名包名的拼写距离；查已知漏洞库。
5. 任何一项**无法确认** → 标 yellow 交人工，禁止猜测放行。

## 修复模式

- 幻觉 API：替换为实际版本真实存在的等价 API，并在注释注明所依据的版本。
- 版本错配：显式 pin 依赖版本，或改写用法匹配锁定版本。
- 幻觉/可疑依赖：移除并替换为可信主流包；确认恶意的上报并全仓排查引用。
- 未核验依赖一律不进 lockfile。

## 验证方式

1. import 冒烟 + 每个外部调用的最小真实调用用例通过（非 mock 替身）。
2. 类型检查/静态分析无未知符号告警。
3. 依赖核验记录（包名、版本、registry 核查结论）写入证据包，可复算。
