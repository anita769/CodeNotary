# 需求歧义扫描 SOP

AI 面对模糊需求的默认行为是「自信地猜」而非追问。契约是后续盲测对抗的唯一依据，
带着猜测冻结契约，整条流水线就在验证一个错误的目标。本 SOP 在冻结前做最后扫描。

## 识别信号

- acceptance 中出现无量化词：「合理的」「正常的」「尽快」「尽量」「等等」「适当的」。
- 边界未定义：「支持大文件」——多大？「处理异常输入」——哪些算异常？
- 隐含假设：需求说「用户」但没说哪种角色；说「排序」但没说升序降序、稳定性。
- 主语或单位缺失：「超时后重试」——谁超时？超时多久？重试几次？
- acceptance 无法直接转写成一条可执行断言。

## 定位步骤

1. 逐条过 acceptance：每条问「我能在不看实现的情况下把它写成测试断言吗？」不能即标记歧义。
2. 列出文中全部无量化词与模糊副词，逐个追问具体阈值或反例。
3. 列出全部未定义名词（角色、实体、状态），确认每个都有唯一解释。
4. 核对 in_scope / out_of_scope：凡「显然不用做」的，必须显式写进 out_of_scope——AI 的「显然」和人的「显然」经常不同。
5. 对每条歧义生成候选解释清单，而非只标「不清楚」。

## 修复模式

- 无量化词一律替换为具体阈值：「尽快」→「P95 延迟 < 200ms」。
- 每条 acceptance 落成「给定 X，期望 Y」的可测句式。
- 隐含假设显式化，写进契约正文或约束节。
- 无法当场消除的歧义写入 open_questions，**标 yellow 交人工澄清，禁止带猜测冻结**。

## 验证方式

1. 每条 acceptance 可直接转化为至少一个测试用例，且转化过程不需要再做任何假设。
2. open_questions 为空，或每个遗留问题都有人工书面答复记录。
3. contract 冻结哈希生成前，由 contract 角色确认扫描清单全部勾选。
