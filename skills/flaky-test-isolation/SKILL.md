# flaky 测试隔离与处理 SOP

间歇性失败的测试会腐蚀整个测试套件的信任度。本 SOP 规范处理流程。

## 识别信号

- 同一测试在相同代码下时而通过时而失败。
- 失败与并发、时间、随机种子、网络、测试执行顺序相关。
- CI 上失败但本地无法复现（或反之）。

## 定位步骤

1. 先隔离：用标记（如 `pytest.mark.flaky`）把该测试从关键路径摘出，避免阻塞流水线，但必须在工单系统登记，禁止无声忽略。
2. 收集失败样本：记录失败时的日志、时间戳、随机种子、执行顺序。
3. 高频复现：循环单跑该测试（如 `pytest --count` 或 shell 循环 100 次）统计失败率。
4. 排查常见根因：
   - 共享状态：测试间通过全局变量、数据库、文件系统互相污染。
   - 时间依赖：`sleep` 等待不足、依赖当前时间、时区假设。
   - 并发竞态：线程/异步任务完成顺序不确定。
   - 外部依赖：网络、端口占用、系统资源。
   - 顺序依赖：单独跑通过、全量跑失败（或反之）。

## 修复模式

- 每个测试自带独立的 fixture/临时目录/数据库事务，不共享可变状态。
- 时间依赖改为注入时钟或 mock 时间，不用 `sleep` 赌时序。
- 并发断言改为「等待条件成立」而非「固定延时后断言」。
- 外部依赖一律打桩或走本地 fake 服务。
- 修复后按原失败率量级放大验证（原来 1/100 失败就至少跑数百次）。

## 验证方式

1. 修复后循环执行该测试足够多次，失败率降为 0。
2. 单独跑与全量跑均通过。
3. 移除隔离标记，把测试放回关键路径，并关闭工单。
