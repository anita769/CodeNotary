# 边界条件核查 SOP

边界缺陷是最常见、也最隐蔽的一类 bug。本 SOP 给出标准化的排查顺序。

## 识别信号

- 测试在空输入、单元素输入、最大/最小值输入下失败。
- 循环结果少一个或多一个元素（off-by-one）。
- 比较处行为与需求描述差一个等号（`>` 写成 `>=` 或反之）。
- 运行时报 `IndexError`、`KeyError`、`TypeError: NoneType`。

## 定位步骤

1. 列出函数所有输入的边界取值：空集合、单元素、0、负数、最大值、None。
2. 检查每一处比较运算符：需求中的「超过/至少/不超过」分别对应 `>` / `>=` / `<=`，逐个对照确认。
3. 检查循环与切片区间：`range(n)` 与 `range(n+1)`、`[a:b]` 是否含端点，必要时代入 n=0、n=1 手算。
4. 检查空集合路径：`[]`、`{}`、`""` 进入函数后是否触发除零、取下标、`max/min` 空序列异常。
5. 检查 None 路径：所有可能返回 None 的调用点，下游是否做了判空。

## 修复模式

- 比较运算符与需求语义对齐，并在注释中写明语义（如「含端点」）。
- 循环边界用「代入最小输入手算一遍」确认，不凭直觉改 `+1`/`-1`。
- 空集合提前返回或给出默认值，不在后续逻辑里隐式假设非空。
- None 用显式 `is None` 判断，不用真值测试代替（`0`、`""` 会被误判）。

## 验证方式

1. 为每个边界取值补一个测试用例（空、单元素、端点、None）。
2. 全量回归测试通过。
3. 让评审者专门复核比较运算符与循环端点，二次确认。
